# 下一阶段研究里程碑（Gate 1–4）

日期：2026-11-07。状态：采纳并细化；不是伦理批准，也不是临床方案。

## 0. 总原则

项目下一阶段应从“继续扩展 UI”转向：

> **建立真实信号到自报经验的可复现测量闭环。**

但必须保留这条科学边界：

> **能产生符号体验，不等于已经证明这种体验对应稳定的前语言心理结构。**

以及：

> **信号与自报相关，不等于信号已经测量了“潜意识”或某个心理构念。**

Gate 顺序不能跳。UI 扩展不是当前瓶颈。

## 1. 对原提案的两点修正

### 修正 A：Gate 2 拆成“管线”与“测量有效性”

原 Gate 2 主要验证信号输入、时间戳、重连、缺失、断开、撤回和设备记录。这些是必要的工程条件，但还不足以支持 Gate 3。

建议拆为：

- **Gate 2A — Pipeline validity**：真实设备接入、时间戳、采样率、丢失、重连、撤回、回放、设备/固件记录。
- **Gate 2B — Measurement validity**：特征提取可复现、传感器质量、伪迹排除、重测稳定性、已知信号阳性对照。

如果 2B 不通过，Gate 3 的人类数据会被“管线正确但测量不可靠”污染。

### 修正 B：Gate 3 拆成“先导”与“独立复现”

原 Gate 3 把采集、个体内关联和阴性对照放在一个阶段。建议拆为：

- **Gate 3A — Preregistered pilot**：伦理批准、预注册、小规模纵向数据、预先指定的个体内估计与阴性/阳性对照。
- **Gate 3B — Independent replication**：独立样本、独立分析者或独立站点复现；不是同一批数据换一种模型。

只有 3A 通过且 3B 复现，才进入 Gate 4。

## 2. Gate 1 — 工程发布可信性

目标：让外部研究者能安全地安装、使用、撤回和验证本机原型。

必须满足：

- 文档、版本号、release notes、checksums 一致
- 全量 CI 通过：unit、E2E、desktop Rust、audit
- macOS/Windows/Linux 至少各一次人工安装/启动/退出验收
- 应用锁、删除全部、旧数据迁移、恢复锁屏、local-files 清理
- 明确的安全退出流程：
  - 随时离开象征空间
  - 急性痛苦/自伤/他伤风险时停止并寻求现实支持
  - 本机急停/退出入口
  - 不需要解释才能退出
- 签名/公证条件满足后，才发正式 v0.1.3；在此之前只能标记为 **unsigned research build**，不能称“已签名”
- 不把“能安装”当成“可临床使用”

Gate 1 通过后，才有资格对外说“可复现的研究原型”。

## 3. Gate 2A — 真实信号管线

目标：证明真实设备数据能被可靠、可审计地接入。

必须记录：

- 设备型号、厂商、固件版本
- 采样率、通道数、通道配置
- 设备时钟来源与主机时钟偏移
- 丢包/重复包/乱序包
- 连接、断开、重连、重连次数
- 采样间隔分布、最大间隔、抖动
- 电极/传感器接触质量（设备支持时）
- 每个 session 的 source、开始/结束、原始包计数、有效样本计数
- 用户显式撤回与删除

必须测试：

- 真实设备连续采集
- 已知注入的丢包、抖动、重连
- 设备断开/恢复
- 应用重启后的恢复
- 时间戳单调性与跨设备对齐
- 撤回后摘要与原始数据（若保存）都删除

Gate 2A 通过条件：真实设备上可重复完成上述测试，且所有异常都有明确标记，不被静默丢弃。

## 4. Gate 2B — 测量有效性

目标：证明“信号 → 特征 → 研究变量”的链路不是黑箱。

必须做：

- 固定特征提取版本与参数
- 原始数据或可重算的确定性特征留存策略（单独同意）
- 传感器质量指标与预先定义的排除规则
- 重测稳定性：同一状态/同一设备的重复测量
- 已知信号阳性对照：例如 paced breathing 对呼吸/心率变异的影响
- 伪迹/运动/接触不良的标记与敏感性分析
- 特征对采样率、滤波、缺口处理的敏感性分析

如果当前产品只保存摘要而不保存原始信号，必须明确：

> 摘要足以做产品反馈，但不足以支持可复现的 LSM-0 研究。

Gate 3 需要单独的研究数据采集与同意，不应把产品摘要直接当作研究原始数据。

Gate 2B 通过条件：特征提取可由第二人从留存数据重算；重测/阳性对照结果符合预注册预期；排除规则不会事后改变。

## 5. Gate 3A — LSM-0 预注册先导

目标：在伦理批准与预注册之后，检验真实信号与自报经验的个体内关联是否超过预定义对照。

### 先决条件

- 伦理/IRB 批准
- 知情同意与撤回流程
- 数据管理计划（原始信号、摘要、导出、删除、保留期限）
- 预注册：假设、主要终点、特征、排除规则、分析、样本量/精度依据、阴性/阳性对照
- 设备/固件锁定
- 分析代码版本锁定
- 独立分析者或至少盲法分析流程

### 设计建议

- 个体内、纵向、重复 session
- 主要估计量：同一参与者的信号特征与自报强度/确定度/主动选择的关联
- 不是组间相关；不以 group median 代替个体
- 预先指定主要信号特征，避免“每个通道都试一遍”
- 预注册缺失数据处理与质量排除
- 样本量与“小规模”应按估计精度/模拟确定，而不是先写一个漂亮数字

### 对照

- 确定性打乱信号（现有阴性对照）
- 保留自相关结构的 surrogate/phase-randomized 对照（如适用）
- 设备关闭/无信号条件
- 已知阳性对照（paced breathing 等）
- 阴性结果必须报告，不得只报告显著参与者

### 分析

- 报告每个参与者的估计与不确定性
- 可报告置信区间/贝叶斯区间；如使用 p 值，必须预注册且不作事后挑选
- 多重比较、停时规则、排除规则全部预注册
- 不把相关性解释为因果、潜意识读取或临床有效性
- 不将“符号参数能由信号预测”直接写成“符号参数反映潜意识结构”

### Gate 3A 通过条件（需在预注册中具体化）

- 数据质量达到预先定义的可用 session 比例
- 预先指定的个体内关联在多数可评估参与者中方向一致
- 阴性对照未产生同等强度的关联
- 阳性对照显示管线对已知变化敏感
- 结果不依赖单一排除规则或单一模型
- 安全性/退出流程无严重问题
- 结果由独立分析者复核

如果 3A 失败：停止 LSM-1，不把失败改写成“个体差异”；可以保留界面与描述性工具。

## 6. Gate 3B — 独立复现

目标：排除单一样本、单一设备、单一分析者的偶然性。

必须：

- 独立样本（最好独立站点/招募批次）
- 独立分析者或预注册的自动分析
- 相同预注册的主要终点与排除规则
- 报告原始效应量与不确定性，而不是只报“显著/不显著”
- 失败也发表/记录

Gate 3B 通过后，才允许讨论“可重复、可泛化的结构”。  
注意：即使复现，也只支持“在该设备、该协议、该人群中的测量关联”，不等于临床有效性。

## 7. Gate 4 — LSM-1 / LSM-2

### LSM-1 — 个体纵向模型

只有 Gate 3B 通过后才开始。要求：

- 预先指定预测目标与评估窗口
- 用 out-of-sample / 嵌套交叉验证，不能用同一批数据既选特征又报性能
- 与简单基线比较：自报历史、session 序号、随机基线
- 报告校准、误差、缺失与退出
- 个体模型必须允许用户查看、覆盖、删除

### LSM-2 — 基于信号的闭环符号空间

这是更高风险阶段。只有 LSM-1 在独立样本中显示稳定、可解释、超出基线的价值，并且有实时质量/安全/退出机制后才考虑。

LSM-2 需要：

- 实时信号质量门控
- 明确的“信号不驱动解释”的 UI 边界
- 用户随时覆盖/退出/删除
- 安全事件与停止规则
- 新的伦理审批与研究协议

## 8. 关键分界线

建议把“结构证据”拆成可证伪的阶梯：

1. **L0 管线可重复**：同一输入能重算出同一特征。
2. **L1 测量可靠**：特征与自报在重测中稳定。
3. **L2 个体内关联**：真实信号与自报的关联超过阴性对照。
4. **L3 独立复现**：独立样本/分析者复现。
5. **L4 增量信息**：符号参数在信号与自报之外提供可复现增量。
6. **L5 预测/干预价值**：out-of-sample 预测或安全干预有效。
7. **L6 临床价值**：需要临床研究与监管，不在当前范围。

当前项目只在 **L0 的工程部分**有基础；L1–L6 尚未开始。

## 9. 当前状态（2026-11-07）

- LSM-0 是描述性基线：稳定性、Spearman、确定性打乱对照；无 p 值、无临床结论。
- 没有真实 BCI 硬件数据。
- 没有伦理批准的参与者数据。
- 产品默认不保存原始信号；只有摘要。
- 没有独立复现。
- v0.1.3 尚未发布；签名/公证未完成。

因此当前不能回答“前语言心理结构是否稳定”，只能回答“测量管线是否值得进一步验证”。

## 10. 立即执行（不依赖外部资源的部分）

1. 写 **LSM-0 protocol v1**：假设、主要终点、特征、对照、分析、排除规则、样本量/精度依据。
2. 写 **preregistration skeleton**（OSF 或机构平台）。
3. 写 **Gate 2 checklist**：设备/固件/时钟/丢包/重连/撤回/原始数据留存。
4. 建立 **hardware-in-the-loop harness**：注入已知丢包/抖动/重连/延迟，验证质量指标。
5. 增加 **阳性对照**：已知呼吸/心率变化下，管线应检出预期方向；阴性对照保持无关联。
6. 定义 **研究数据 schema**：设备元数据、原始/特征数据、质量标记、撤回状态；与产品摘要分开。
7. Gate 1：完成安全退出流程、平台 QA、签名/公证后的 v0.1.3；在签名前只发 unsigned research build。
8. 建立 **独立复现包**：预注册、分析代码、容器/脚本、脱敏数据字典。

## 11. 需要外部输入的决策

- 真实设备：OpenBCI / BrainFlow / LSL 的具体型号、SDK、固件
- 原始信号留存与同意范围
- 伦理/IRB 与招募伙伴
- 预注册平台与主要终点
- 样本量与精度目标
- 签名/公证凭据
- Windows/Linux 人工 QA 环境

## 12. 不做什么

- 不在没有 Gate 2B 的情况下采集 LSM-0 人类数据
- 不把产品摘要当作研究原始数据
- 不把“符号体验生成”写成“前语言结构已被证明”
- 不用同一批数据既选特征又报性能
- 不在 LSM-1 未复现前做 LSM-2 闭环
- 不把阴性对照做成走过场
- 不继续用 UI 扩展替代实证问题
